# Doubt-Driven Development
Core Methodology: Subjects every non-trivial decision to a fresh-context adversarial review before it stands; biased to disprove, not validate.

Key steps:
1. CLAIM — Name what stands
2. EXTRACT — Smallest reviewable unit (artifact + contract only, strip reasoning)
3. DOUBT — Adversarial stress-testing (look for unstated assumptions, edge cases, failure modes)
4. RECONCILE — Classify findings (contract misread, valid+actionable, valid trade-off, noise)
5. STOP — Bounded cycle (met criteria or stop condition)
